BaCoN - Tutorial

Thomas Rohde

Feb 22, 2025

This vignette describes how to predict functional buffering between gene pairs using BaCoN, using data from the Cancer Dependency Map (DepMap).

0. Install BaCoN package

if(!require(devtools)) {install.packages("devtools")}

1. Import packages

2. Data preparation

This script depends on DepMap gene expression data as well as Chronos scores, available at the DepMap portal.

Please download the files and place them in the “data” directory.

  • Chronos scores: “CRISPRGeneEffect.csv”
  • Gene expression: “OmicsExpressionProteinCodingGenesTPMLogp1.csv”

2.1 Import DepMap gene expression and fitness effect data


import_depmap <- \(filepath) {
  object <- as.matrix(data.table::fread(filepath), rownames = 1)
  colnames(object) <- stringr::str_split_i(colnames(object), " \\(", 1)
  return(object)
}

ge_complete <- import_depmap(
  file.path("..", "data", "OmicsExpressionProteinCodingGenesTPMLogp1.csv"))

chronos_complete <- import_depmap(

for (i in 1:ncol(chronos_complete)) {

2.2 Subset expression and fitness effect matrix

The gene expression and the Chronos score matrix are reduced to the cell lines that are represented in both datasets.

intersecting_cell_lines <- intersect(rownames(ge_complete), rownames(chronos_complete))

ge_subset <- ge_complete[intersecting_cell_lines,]
chronos_subset <- chronos_complete[intersecting_cell_lines,]

The correlations are computed across 1103 interesecting cell lines.

Conceptually, we expect that biologically meaningful buffering predictions require the buffering partner to be expressed in a sufficient number of cell lines and the knockout of the buffered partner to have a certain impact on cellular fitness. Our experience showed that removing genes with low signal by applying a threshold on the expression level improves buffering predictions.

This is only one possible strategy. In contrast to correlation scores, BaCoN scores are compared with and thus influenced by all other gene partners of the respective pair. It is recommended to experiment with different matrix sizes.

To keep runtimes low, we apply very strict thresholds in this vignette. In a comprehensive analysis, it is strongly recommended to cover a larger fraction of the genome, by defining less strict thresholds.

Matrix sizes of ~ 6000-16000 genes on each side of the matrix showed good results in our experiments. The cell lines should be kept at a high number

# We restrict the gene space to genes that do not show an expression (log2 TPM+1)
# of > 5 in at least 1000 of the cell lines.

3.1 Compute PCC correlation matrix:

prediction_matrices[,,"PCC"] <- cor(ge_subset, chronos_subset, 
                                    use = "pairwise.complete.obs")

3.2 Compute BaCoN matrix:

BaCoN may behave unexpectedly if the input correlation matrix is formatted in an unexpected way. To ensure stable and reliable results, please ensure that the input matrix…

  1. is a correlation matrix or composed of comparable values scaling between -1 and 1. BaCoN is currently not designed to work e.g. on negative logarithmic p-values or other association indices.

  2. does not contain NAs. This should not cause problems in cases of single NA values, but entire NA rows or columns should be removed from the matrix.

  3. should not have duplicated row- or column names. Each gene should be represented in one row and/or column only.

prediction_matrices[,,"BaCoN"] <- BaCoN(prediction_matrices[,,"PCC"])

4. Cholesky whitening + PCC + BaCoN

Next, we combine BaCoN with the pre-hoc covariance normalization method Cholesky whitening, as proposed in our manuscript. We use the whitening package and its whiten function.

if (F) {install.packages(whitening)}
library(whitening)
#> Lade nötiges Paket: corpcor

We whiten both input matrices independently. It is important that the cell lines of both objects are identical and in the “columns” dimensions of the object. Therefore, we transpose the objects before and retranspose them after the whitening.

whitened_ge_subset <- t(whiten(t(ge_subset), method = "Cholesky"))
whitened_chronos_subset <- t(whiten(t(chronos_subset), method = "Cholesky"))

prediction_matrices[,,"Cholesky_PCC"] <- cor(
  whitened_ge_subset, 
  whitened_chronos_subset, use = "pairwise.complete.obs")

prediction_matrices[,,"Cholesky_BaCoN"] <- BaCoN(prediction_matrices[,,"Cholesky_PCC"])

5. Collect top 100 predictions:

We use the lowest BaCoN score of the top 100 predictions as cutoff. The high density of paralog pairs is clearly visible. This can lead to more than 100 pairs in the prediction set, as the top BaCoN-scored pairs are often tied. We use the PCC score to deal with the tied pairs.

predictions <- data.table(data.frame(
  expression_gene = rep(rownames(prediction_matrices), 
                        ncol(prediction_matrices)), 
  chronos_gene = rep(colnames(prediction_matrices), 
                     each = nrow(prediction_matrices)), 
  sapply(dimnames(prediction_matrices)[[3]], 
         \(.) as.vector(prediction_matrices[,,.]), simplify = F)))

predictions[order(BaCoN, PCC, decreasing = T), BaCoN_rank := .I]

Summary

The exponentially increasing runtime of BaCoN is due to the greater number of required computations, but also the handling of very large objects. The data.table environment is designed to optimize speed and RAM usage when dealing with large datasets. The function is designed to minimize runtime increase caused by data handling, as well as RAM usage.

Future versions of BaCoN might offer further runtime improvements.
